# Agile Workflow

## Method

Use a lightweight Scrum/Kanban hybrid with one-week sprints. A short sprint cadence keeps research uncertainty visible while preserving a demonstrable increment every week.

## Workflow

`Backlog -> Spike/Ready -> In Progress -> Review -> Validation -> Done`

## Sprint Events

- Planning: choose a small outcome and confirm dependencies.
- Daily check: report completed work, next action, and blocker.
- Review: demonstrate the increment against acceptance criteria.
- Retrospective: record what to continue, stop, and change.

## ML-Specific Rules

- Spikes must produce a decision or evidence, not only exploration.
- Dataset changes require a recorded version and impact note.
- No metric is accepted without split and feature provenance.
- A better score with leakage is a failed result.

## Change Control

New scope enters the backlog. P0 compliance work takes precedence over visual polish. Any change to the model target or data contract requires updating the related planning documents before implementation continues.
